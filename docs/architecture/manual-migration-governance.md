# Manual database release governance

**Do not modify numbered migrations after production execution. Create a new forward migration.** For this release, SQL 001–068 are frozen regardless of whether their execution can be proven. Historical execution remains UNVERIFIED unless a separate trustworthy execution record establishes otherwise. File presence, schema similarity and a successful verification are not proof of migration execution.

The former statement that 001–006 were deployed and 008–010 pending was a historical review assumption, not current environment evidence. 007 is diagnostic only. Do not use that old boundary to select scripts for replay.

The authoritative process is documented in [AUD-010 remediation and Development rollout](../database-release-governance-7a.md). Its locked artifact inventory, required schema contract and source manifest live in `database/releases/`. Current master was reviewed through SQL 068; the new forward migration is `sql/manual/069_database_release_governance.sql`.

`npm run migrate` now produces an offline plan. It does not connect or execute migrations. `npm run migrate:down` deliberately fails; financial and clinical evidence must be corrected through a reviewed forward migration. Do not invoke node-pg-migrate directly against hosted environments or treat the numbered manual directory as a sequential replay queue.

An owner manually executes a reviewed bundle generated by `npm run db:plan -- --environment development --actor <operator> --release <immutable-release-ref> --output <review-file.sql>`. Only actual transactional forward execution creates an APPLIED receipt. The separate current-schema attestation does not certify historical execution. A bare SQL 069 execution creates the structures but cannot classify a release as ready.

No hosted database was inspected or modified by this remediation. Deployment must follow verification, database-owner review, restricted runtime credential configuration, and manual release approval. Keep `LIVE_ROUTING_ENABLED=false`; this process does not enable Approval Engine V2.
