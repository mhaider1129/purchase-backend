# Phase 5A item-identity inventory

## Method and classification

Repository-wide SQL, JavaScript, JSX, tests and architecture documents were searched for item/product/catalog/stock names, codes, descriptions, manufacturer identifiers, external identifiers and UOM conversions. “Active” below means reachable production code, not proof that deployed rows exist. Multiple labels are used where an entity is both legacy and scheduled for migration.

## Legacy migration rule

For each `item_master` or `item_master_items` row: profile → steward selects/creates Generic → write `legacy_item_mappings` and alias → infer Approved Product **only** when manufacturer plus stable MPN/product evidence exists → retire legacy creation after callers cut over. A generic/brand/name resemblance alone is insufficient product evidence.

## Disconnected identities

Highest-risk disconnected identities are legacy `item_master_items` creation, exception-created stock rows, free-text contract items, request/import paths that do not invoke governed validation, and PO/GR/inventory columns that exist but are not populated. `item_variants`, legacy `item_conversion`, merge completion, controlled brand, and catalog-to-contract-line relationships are incomplete or disconnected.
